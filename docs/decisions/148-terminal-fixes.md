| 28 Nov 2026 | Copying uses Paradev's `terminal-copy` whole, through every copy path (the copy key, copy on select, the menu's Copy, the terminal's `copy` event). Where the clipboard cannot be written the page falls back to nothing, as its other copies do, not to Paradev's native copy; `terminal-clipboard.test.ts` is not ported. Its Ghostty parity tests run on a real xterm 6 instead of `@xterm/headless`. | The rules are what the brief asked for, and one function for every copy keeps them from being half applied. A native fallback needs a Tauri clipboard plugin, a new dependency, and `@xterm/headless` is not installed. xterm keeps the selection mode in a private field, so a browser spec reads it and fails if a bump removes it. | Claude | `engine-copy.ts`; call `term.getSelection()` again in `engine-input.ts` and `TermMenu.tsx` |
| 28 Nov 2026 | Paradev's `bareWebUrl`, `pathText`, word links, styled-text links, the whole-line fallback and its search for a file by name are not lifted; `fileLocation`, the parser, its fallbacks and the buffer helpers are. A candidate is asked about only if it has a `/` or ends in an extension, and not when it is part of a web address or a `host:port/` path. | `bareWebUrl` needs `tldts` (a new dependency, which needs the owner's yes); the others would ask the shell about every hovered line, and the parser reads any word followed by a number (`here, 3`) as a path and its line. | Claude | `engine-paths.ts` (`looksLikePath`, `planOf`); lift the rest later with the owner's yes to `tldts` |
| 28 Nov 2026 | A file link opens only a file inside the terminal's session folder, and both sides check: the page never asks about a path that reads as outside, and the shell reads the real path (links followed, `..` resolved) before it answers and again before it starts anything. A folder, a missing file and an outside file all answer none. | The brief's rule, and the page must not be the only guard. Answering the same for all three lets the page learn nothing of what is outside. | Claude | `insideFolder` in `engine-paths.ts` and `file_in_folder` in `folder_open.rs`, each with a test that fails without it |
| 28 Nov 2026 | The line is passed only where the editor's own documentation says how: VS Code and Cursor `--goto file:line:col` (each one's `--help`, read on this Mac), Zed `file:line:col` (zed.dev/docs/reference/cli, not installed here), Xcode `xed --line n file` (`xed --help`, read here). Windsurf's documentation names no option (docs.windsurf.com's `llms-full.txt` read in pieces and searched: it names the `windsurf` command only for putting it on the PATH, and a few pages came back cut off, so a mention in a cut part is not ruled out), so its file opens with no line. A path with a `:` in it opens with no line. No editor was launched to check. | A flag is not guessed (the same rule item 107 kept for JetBrains). The documented forms were read and their argument lists are tested; a real launch would open windows on the owner's Mac. | Claude | `Line` and `EDITORS` in `folder_open.rs` |
| 28 Nov 2026 | On a Mac with the app bundle, a file opens through the program inside the bundle that takes a line (VS Code's and Cursor's `Contents/Resources/app/bin/`, Zed's `Contents/MacOS/cli`, Xcode's `xed`), and with none through `open -a <app> <file>` with no line; the `code` on the PATH is used only off macOS or with no bundle. | `code` on this Mac is a link into Cursor.app, so the PATH would open the wrong editor; item 107 already prefers the bundle for the same reason. Zed's bundle path is in its docs; VS Code's and Cursor's exist here. | Claude | `editor_file_launch` in `folder_open.rs` |
| 28 Nov 2026 | The editor call is item 107's `session_open_in_editor`, with an optional file, row and column, and a new `session_files_in_folder` for the check; no new editor is added to the list. The mock host answers both for the browser specs. | The brief says to open through item 107's call, by id, never a typed command. | Claude | `folder_open.rs`, `lib.rs`, `host.ts` |

| 28 Nov 2026 | File links work in TERMINALS rows (the row's folder, or a lane's own), and in a bottom-panel pane only when its shell started in the folder it was asked for. | A pane whose folder was gone starts in the home folder, and every file under the home folder would count as inside it. | Claude | `terminals.ts`, `terminal/terms.ts` (`setTermFolder`) |
| 28 Nov 2026 | The reclaimer runs when the agent program the app's shell started for the terminal exits (`terminals.ts`, `programEnded`), not when `session-fg` says an agent is no longer in front. An agent the person starts by hand inside a Shell row, and a Shell row itself, give nothing back. | `session-fg` says which program is in front, never that it ended: an agent stopped with Ctrl+Z looks the same, and taking the modes of a stopped agent breaks it when it comes back (Paradev accepts that risk with its marker; here there is no marker). The brief says to key on the end of the agent process. Reset in the terminal's menu stays for the rest. | Claude | `terminals.ts` |
| 28 Nov 2026 | Beyond Paradev's three (Kitty keys, mouse, focus), the reclaimer turns off bracketed paste and application cursor keys when xterm shows them on (Paradev's reset for a brand-new shell), and leaves the alternate screen when the program entered it with `?1049h` (Paradev does not). The Kitty escapes are written again after leaving it, since xterm keeps the flags for each screen. | The brief lists these modes. The shell is not yet running when the program's exit is read, so turning them off cannot take a shell's own. Leaving the alternate screen costs the dead agent's last frame, and a program that entered with `?47h` or `?1047h` is left alone, since `?1049l` would restore a cursor nothing saved. | Claude | `engine-reclaim.ts` (`keysOff`, `takeBackModes`) |
| 28 Nov 2026 | The reclaim is written at once and again after what the program printed has been read, and the reclaimer's epoch begins when the terminal is made. | A line the owner writes right after the exit would otherwise land on the alternate screen and go when it is left. Paradev calls whatever is on before its first prompt marker the shell's own; here the agent is the program from its first byte, so nothing is. | Claude | `programEnded` in `engine.ts`, `sharedFor` in `engine-reclaim.ts` |
