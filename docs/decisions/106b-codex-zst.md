# Item 106b: Codex's compressed sessions

| Date | Decision | Why | By | Undo by |
| --- | --- | --- | --- | --- |
| 27 Nov 2026 | `compressed` keeps its place in the counts but changes its meaning: it now counts compressed Codex rollouts that could not be unpacked (corrupt or cut short), and the page's words say so (English first, copied into ja, ko and zh) | The counts' names and the TypeScript shapes stay as they are, so no page code changes, while the words stop saying "not read yet", which would now be false. A rollout that unpacks adds to the counts as a plain one does | Claude | Rename the field and its words if a separate count of "could not be unpacked" is wanted next to a count of compressed files seen |
| 27 Nov 2026 | A compressed rollout that inflates past the cap is counted `too_big` in the usage scan, as a plain file over the cap is; in the first-launch import it cannot happen, because the import reads only the first 256 KiB of a file and stops | One word for "too large" whichever way the file is stored. The import never needs the rest of a file, so it is never refused for one | Claude | Give `Skip::TooBig` its own count |
| 27 Nov 2026 | A compressed rollout is charged to a scan's 256 MiB byte budget at eight times its size on disk | The budget is meant to bound what is read and parsed. A compressed file's size understates that by about ten; eight is a round figure under the usual ratio that keeps the budget meaningful without decoding the file twice to measure it | Claude | Change `ZST_RATIO` in `outside_use.rs` |
| 27 Nov 2026 | The list rows and a past conversation's last messages (past_chats.rs) read compressed rollouts too, not only the two counting readers the item named | Reading "these sessions as plain `.jsonl` rollouts" means the + menu and History must show them: every Codex session on the owner's Mac is compressed, so counting them but never listing them would leave the same hole. A file's tail is found by decoding the stream once and keeping the newest 1 MiB, since a compressed stream cannot be sought | Claude | Revert `lines_in`, `last_part` and `head_until`'s compressed branches in `past_chats.rs` |
| 27 Nov 2026 | One cap for all readers: 32 MiB of decompressed output, `outside_use::Limits::file_bytes`' own default and so the budget the plain reader gives one rollout; the decoder's window is held to 32 MiB, and at most the cap plus 64 KiB of compressed input is read | A zstd file of a few kilobytes can inflate to gigabytes, so the output is counted as it is produced and the byte after the cap is refused. Holding a compressed rollout to a plain one's budget means neither can cost more than the other. A frame that asks for a window above the cap is refused before it allocates, where ruzstd's own default is 128 MiB | Claude | Change `CAP` and `WINDOW_MAX` in `zst.rs` |
| 27 Nov 2026 | `ruzstd` is pinned at exactly 0.9.1, with `default-features = false, features = ["std"]`: its `hash` feature is left out | 0.9.1 (published 11 Oct 2026) is the newest release and is over two weeks old; 0.9.0 (26 Jul) and 0.8.3 (8 May) are older, and 0.7.0 to 0.7.2 are yanked. The default `hash` feature adds a second crate, `twox-hash`, which the lockfile does not hold, and the owner allowed one crate. The hash only verifies a frame's optional content checksum; a damaged or cut-short file is still refused by the decoder's own checks (tested: truncation at several places, junk, a damaged middle) | Claude | Turn the default features back on in `Cargo.toml` (then `twox-hash` enters the tree and needs the owner's word) |
