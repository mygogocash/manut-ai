A development build started beside the installed app takes the socket, and the installed app's relays then reach the development build until it quits | Claude | Name it by pid and have the relay pick the newest running app's |
| 27 Nov 2026 | Item 103a: each relayed call has a connection of its own, and the relay closes it when the program cancels the request or closes the relay's input; the door reads a closed connection as the call given up, closes it and tells the page | MCP's `notifications/cancelled` names one request; a connection per call lets the relay close exactly that one, and an end of file is something the door can read without a second message on the socket | Claude | Keep one connection per relay and add a cancel line to the socket's protocol |
| 27 Nov 2026 | Item 103a: a call id is a counter (`tm-1`, `tm-2`), not a random token | Only this app's own page can answer a call (a Tauri command), so an id needs to be unique, not secret; a counter keeps the tests' ids readable | Claude | Make `Door::new_id` draw 16 random bytes as `hub.rs`'s `token` does |

| 27 Nov 2026 | Item 103a: a reply that reaches the door in the same moment the call closes (the program gave up, or ten minutes passed) is still the answer the program hears | The person's press may already have acted (a message sent); answering with what happened is truer than saying the card closed. | 27 Nov 2026 | Item 103a: the section is not offered in the Mac App Store edition | Its sandbox was not checked against a socket that another program's relay reaches, nor a relay run by another program from inside the sandboxed bundle | Claude | Drop `APP_STORE` from `threads_mcp::available` once checked |
